# 课表以「周次规则 + 例外」存储，不存每周快照

## 背景与决定

教务系统表达排课的方式本身就是规则：一条 `(1-12,4J410(主校区))` 表示"第 1 到 12 周的每次都在 4J410"，而 `停课`、`线上教学` 是挂在规则上的单周例外，调课则根本不进课表（只在教务系统的通知里）。

因此本地存储以**规则**为单位：一条「上课安排」承载（课程 / 教师 / 周次集合 / 连续节次跨度 / 地点），单周的变化记为例外条目挂在它上面。不采用"把第 1-18 周每周的格子算出来存死"的快照方案。

## 理由与代价

存快照会让"改一次课"变成"改一堆快照"；学期中途教务系统一改课表，快照就整片失准。存规则能逐字对应教务系统的原文，导入因此变成一次纯粹的翻译。

代价是必须实现并测好**"按周展开"**这段逻辑——它是课表 App 最核心、也最容易写错的部分。它应当是一个不依赖框架的纯函数，并配足测试。

## 影响

- 「桌面小组件」「今日课程」这类视图消费的是**展开后的结果**，不是存储本身；展开发生在读取时。
- 一旦支持手动添加例外（停课 / 调课），数据模型已经就位，不需要改结构。
