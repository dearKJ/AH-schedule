# 用 Flutter 编写，但 v0.1 只面向 Android

## 背景与决定

使用者用 Android 手机，且**没有 Mac**——因此 iOS 端既编译不了也测不了。按常理，只做 Android 就该选 Kotlin 原生。

仍然选择 **Flutter / Dart**。理由有三条，都是明确的：

1. **学习目标**：使用者会一点代码，明确想借这个项目学一门新技术。Flutter 是当下最主流、最能写进简历的移动端方案。
2. **保留退路**：日后拿到 Mac 即可开启 iOS 端，**不需要重写**——代码结构对两端是兼容的。
3. **平台专属部分很小**：只有桌面小组件（v0.2）需要写原生桥接，其余全是 Dart。

## 明确不做的事

**不要为 iOS 做任何假设性工作。** 这是本 ADR 存在的主要理由——否则未来的维护者（或未来的使用者本人）会看到一堆空转的 iOS 配置，以为它们在起作用：

- 不写 iOS 专属配置，不纠结 `Info.plist`、签名、Podfile
- 不引入任何需要 Xcode 才能构建的依赖
- `ios/` 目录保留但**冻结**：它是 Flutter 脚手架自动生成的产物，不代表这个项目支持 iOS
- v0.2 的桌面小组件**只实现 Android 端**

## 后果

- v0.1 的验证只在 Android 真机/模拟器上进行。任何"跨平台正确性"的宣称都是未经检验的。
- 分发方式因此确定为：**直接发 APK**（零成本、零审核）。同学需要允许"安装未知来源应用"。
- 若日后 iPhone 用户成为真实需求，成本的入口是**一台 Mac + 99 美元/年**，而不是重写代码。
