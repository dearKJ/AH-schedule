# 安徽工程大学教务系统 · 课表导出文件格式

**来源**：`http://xjwxt.ahpu.edu.cn` → 课表页 →「导出 Excel」，2026-2027 学年第一学期实测样本。
**一句话结论**：导出的 `.xls` 其实是一份 **GBK 编码的 HTML 文档**，不是二进制 Excel。所以导入功能的实现是「GBK 解码 + HTML 解析」，**不需要 xls/xlsx 解析库**；但也意味着用户若用 Excel/WPS 打开再"另存为"，结构会被改写——导入必须尊重原始文件，不要先转换成真 Excel。

同时它也解释了为什么自动登录抓取在 v0.1 不值得做：既然课表能一键导出成结构良好的文件，抓取省下的只是"点两下"的成本，却要承担登录加密、验证码、学期切换、改版即崩的全部风险。

## 一、页头

| 位置 | 内容 | 说明 |
| --- | --- | --- |
| `<h1>` | `个人课程表` | 固定 |
| `<h3>` | `2026-2027学年第一学期` | 学期名。注意与界面上的 `2026-2027学年1学期` **写法不同**，解析时要归一化 |
| 学生信息行 | `学号:… 学生姓名:… 所属班级:… 总学分:18.5` | **分享前必须剥离**（见 ADR-0002） |
| `<pre>` | `课表格式说明：教师姓名 课程名称(序号) (第n周-第m周,教室)` | 教务系统自己给出的格式说明 |

## 二、表格骨架

`<table id="manualArrangeCourseTable">`，13 行 × 8 列：

- 第 0 行是表头：`节次/周次` + `星期一`…`星期日`
- 第 1–12 行对应第一节…第十二节
- 节次列的底色标识时段：**第一节–第五节 `#EEFF00`（上午）、第六节–第九节 `#33BB00`（下午）、第十节–第十二节 `pink`（晚上）**

## 三、单元格定位（可直接算出坐标）

有课单元格带 `id="TD{n}_{m}"`，**`n = 星期序号 × 每日节次数 + 节次序号`**（星期序号 0 = 星期一，节次序号 0 = 第一节）。样本中 `TD0_0` = 星期一第一节，`TD12_0` = 星期二第一节，`TD2_0` = 星期一第三节。

- 每日节次数在本样本是 12。**解析时应按实际节次行数取步长，不要写死 12**。
- `{m}` 在样本中恒为 0，含义未知，不要依赖。
- `rowspan="k"` = 这条安排**连堂 k 节**（横跨连续节次）。
- 更稳的做法是按 `id` 定位坐标，再用 DOM 顺序与 `rowspan` 交叉校验；纯靠 DOM 顺序推列对齐容易被空格子带偏。

## 四、单元格正文（核心规则）

正文用 `<br>` 分隔，**每两行一组**，组的顺序固定：

```
第 1 行：课程名称(课程号.班号) (教师)
第 2 行：(周次,教室(校区))
```

多个安排同格时依次追加（第 3、4 行是第二条，以此类推）。**空行全部丢弃**——单条安排的单元格里会夹着两个空行，丢掉即可。

**规则已用样本全量验证：7×12 = 84 个格子全部解得出来，0 个无法配对的单元格；其中 8 格有内容，这 8 格一共 16 条正文条目，含 2 条「停课」标记（见下节第 4 点），合并后是 14 条上课安排。**

（早先这里写的是「15 条上课安排」。那个数字与样本本身对不上，逐格数一遍就是上面这些数。以样本为准，见 [`test/fixtures/README.md`](../../test/fixtures/README.md) 的「结构指纹」。）

## 五、已实测的坑

1. **扩展名骗人**：`.xls` 实为 GBK HTML。
2. **教务系统模板自身的 bug**：一个格子里有多条安排时，**除最后一条外，前面每条的周次行末尾都少一个 `)`**（`(1-8,4J209(主校区)` 而非 `(1-8,4J209(主校区))`）。解析正则必须容忍末尾缺括号。
3. **断档周用空格分隔区段**，不是逗号：`(1 3-12,4J410(主校区))` 表示第 1 周 + 第 3–12 周。逗号左侧整体是周次集合，右侧是地点，所以**先按第一个逗号切开，再按空格切周次段**。
4. **停课会额外单列一条**：`(2,停课(主校区))` 与 `(1 3-12,4J410(主校区))` 同格出现。正常那条的周次集合**已经排除了第 2 周**，所以这两条要合并理解为"一次带例外的排课"，**不能当成两次上课**。
5. 空单元格的 `style` 有拼写错误 `backGround-Color:#ffffff`（大小写混排 + 拼错），可用来识别空格子。
6. 有课单元格底色在样本里一律是 `rgb(148, 174, 243)`，无法判断是否按课程分配，**不要依赖它做课程配色**。
7. 导出只含当前学年学期，没有跨学期的课程清单。

## 六、未经样本验证的格式

以下四种格式**在本样本里一次都没出现**，规则来自教务系统的格式说明与使用者描述。导入实现必须为它们写测试用例，但不能声称已验证：

- 单双周：`(单周第5周-第15周,教室)` / `(双周第4周-第12周,教室)`
- 断档周的标准写法：`(第4周-第10周 第12周-第18周,教室)`
- 特定周：`(第12周,教室)`
- 线上教学：`(第14周,线上教学(校区))`

## 七、其他事实

- 该系统**不支持查询他人的课表**（任意班级 / 教师 / 空教室都查不到），所以"查空教室""看同学课表"这类功能没有数据来源；同学之间只能靠分享文件。
- 调课**不出现在课表里**，只在教务系统的通知中出现。

## 八、这个系统是什么（以及为什么它的难点不在导出上）

**厂商与谱系**：不是强智 / 正方 / 青果 / 超星。登录页由 **Beangle** 框架渲染；课表 action 名 `courseTableForStd` 在开源项目 **`openurp/edu-eams-webapp`** 中有对应实现 → 属 **EAMS / URP 谱系**，对应的商业厂商是**上海树维（Supwisdom）**。**长安大学是完全同构的对照校**（`bkjw.chd.edu.cn/eams/`）。

**交叉验证**：长安大学的开源项目 `code-cycler/course_schedule_for_CHD` 记录了同族系统的坐标公式 `index = 星期 × 每日节次数 + 节次`——与本文档第三节从导出文件实测出的 `TD{星期×12+节次}` **完全一致**。另，`lingion/sleepy` 的 `JwClassicEamsParser` 注释中直接点名"安工程 12 节"。

**为什么不做自动抓取**——这里的证据比"不值得"更硬：

- 同族系统的**课表页面**里，HTML 表格是**空壳**：数据只在内联 JS 的 `TaskActivity` 块中，而且**周次是一个 53 位位图**。抓取要解析 JS 位图；导出文件则是服务端渲染好的**干净表格**，本文档第四节的"两行一组"规则即可全量解析。
- 登录**技术上可行**：无验证码，字段为 `username` / `password` / `encodedPassword`，客户端计算 `SHA1(盐 + 密码)`，盐硬编码在页面中、可动态提取。
- **但仍然不做**，理由不是"难"，而是：抓取意味着**要在 App 内保存使用者的教务系统密码**，而这个 App 是以 APK 形式分发给同学的。为省掉"点两下"，去持有几十位同学的教务系统密码，不值得。

来源见 [`docs/research/ahpu-jwxt-and-oss-references.md`](../research/ahpu-jwxt-and-oss-references.md)。该调研所处的环境 **`WebSearch` 全程失效、`WebFetch` 被拦截**，结论来自直连探针、`gh api` 与 pub.dev API，**没有搜索引擎结果做交叉验证**——引用其 star 数与仓库名时请自行复核。
