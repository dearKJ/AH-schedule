## 问题

学校教务系统能看课表，但**不能离线、不能一眼看全、不能提醒、不能分享**。每周要查课就得重新登录一次教务系统，在有课的教学楼里信号还差；一屏只能看见几天，要知道"这周到底哪天满"得来回点；同学之间想对个课表，只能互相拍照。

## 方案

一个 Android App：把教务系统导出的课表文件导入进来，**存在手机本地**，此后离线打开就是一整周的网格，今天高亮，同课同色。课表能手动增删改，能填学期设置（第 1 周的第一天）让"今天"和以后的上课提醒算得准。换手机或想分享给同学时，导出一份**剥掉学号姓名班级**的 JSON 文件传过去。

## 用户故事

### 导入

1. 作为学生，我想选择一个教务系统导出的课表文件导进来，这样我不用一条条手动录入。
2. 作为学生，我想在导入前看到解析出来的课表预览，这样我能确认每一格都对得上，而不是导完才发现有课丢了。
3. 作为学生，我想在预览页直接改掉解析错的格子，这样我不用先保存一份错的再回来修。
4. 作为学生，我想在预览页看到每一处没能解析的内容被**明确标出来**（哪一格、哪一行），这样我能自己补上，而不是让它悄悄消失。
5. 作为学生，我想在导入前被告知这会**整学期覆盖**，这样我不会以为它是往旧数据里合并。
6. 作为学生，我想在导入前被告知**手动标记的例外会被清除**，这样我不会在重导之后才发现停课标记没了。
7. 作为学生，我想导入后看到"解出 N 条上课安排 / 有几处需要留意"的汇总，这样我对这次导入的质量有个判断。
8. 作为学生，我想重复导入同一个学期的文件时整学期被替换掉，这样教务系统改了课表之后我重导一次就同步了。

### 看课表

9. 作为学生，我想一屏看到整周的课表，这样我不用为了知道哪天满而反复切页。
10. 作为学生，我想课表纵向滚动时星期栏吸顶，这样我滚到晚上的课时还记得这是星期几。
11. 作为学生，我想今天那一列被高亮，这样我一打开就知道今天要上什么课。
12. 作为学生，我想在周次之间前后切换，这样我能提前看下周的安排。
13. 作为学生，我想快速跳回当前教学周，这样我在别的周翻完之后不用一路点回来。
14. 作为学生，我想周次导航的范围跟着我实际的数据走，这样我不会翻到一堆空周。
15. 作为学生，我想同一门课在不同格子里颜色一致，这样我扫一眼就能看出这门课这周排了几次。
16. 作为学生，我想同一门课的颜色每次打开都一样，这样我认颜色形成的习惯不会被破坏。
17. 作为学生，我想点开一条上课安排看到详情（课程、教师、地点、校区、节次、周次、以及它对应的具体时刻），这样我能确认在哪上课、几点上。
18. 作为学生，我想在一条安排跨多个节次（连堂）时看到它正确占据那几个格子，这样我不会把它看成三节课。
19. 作为学生，我想在没有课的格子上看到空白而不是占位文字，这样课表的疏密一眼可辨。

### 手动维护

20. 作为学生，我想长按一个空格子来添加一条安排，星期与节次自动带出，这样我补录时不用重复填已知的东西。
21. 作为学生，我想添加课程时课名有历史自动补全，这样我不用每次都把课名敲全。
22. 作为学生，我想编辑一条已有安排，这样教师或教室临时变了我不必删了重建。
23. 作为学生，我想删除一条安排，这样排错了或不再上的课能从表上拿掉。
24. 作为学生，我想用教务系统那套写法输入周次（如 `1-8 10 12-16`、`单周第5周-第15周`），这样我照着教务系统抄就行，不用学一套新语法。

### 学期与时间

25. 作为学生，我想设置"第 1 周的第一天"，这样 App 能算出今天是第几教学周。
26. 作为学生，我想让 App 内置一套默认作息时间表，这样我什么都不用配就能看到每节课的起止时刻。
27. 作为学生，我想修改作息时间表，这样学校调了上课时间之后我的课表跟着对。
28. 作为学生，我想建多个学期并来回切换，这样上学期的课表不会被这学期的覆盖掉。

### 分享与迁移

29. 作为学生，我想把课表导出成一个文件，这样换手机时不用重新导入一遍。
30. 作为学生，我想把这个文件发给同学，这样他们能看到我的课表。
31. 作为学生，我想导出时学号、姓名、班级被剥掉，这样分享课表不等于公开我的个人信息。
32. 作为学生，我想在同学发来的课表文件里导入到我的 App，这样我能把别人的课表加进来对照着看。
33. 作为学生，我想导出的文件里带着格式版本号，这样以后 App 升级了还能读老文件。

### 出错与冲突

34. 作为学生，我想在解析碰到没见过的写法时被明确告知而不是拿到一份看起来正常、实则缺课的课表，这样我不会一学期后才发现某门课从没被提醒过。
35. 作为学生，我想在同一格同一周出现两门课时看到它们**并排标红**、且在详情里列出双方，这样我能自己判断该怎么办。
36. 作为学生，我想 App **不要替我自动取舍**冲突的课程，这样我不会在不知情的情况下丢掉一门课。
37. 作为学生，我想在选错文件（比如选了一个跟课表无关的文件）时得到明确的失败提示，这样我知道该重新选而不是对着空白界面发呆。
38. 作为学生，我想在文件里的周次或节次超出合理范围时被告知，这样我不会默默拿到一份错位的课表。

## 实现决策

### 分层

`lib/core/`（纯 Dart，不 import Flutter）/ `lib/data/`（drift 数据库、仓储）/ `lib/ui/`（Flutter 界面，go_router）。`core/` 不许 import Flutter——这是它作为唯一测试接缝的前提。逻辑不写进 UI：解析、展开、序列化全部落在 `core/`，UI 只负责把结果画出来。

### 数据模型

**学年学期**是隔离单位。切换学年学期 = 切换整张课表。App 内可存多个学年学期。

**上课安排**是课表的最小单位，一条记录承载：

- 课程名称
- 教师
- **周次集合**（周次的唯一内部表示）
- **节次跨度**（起始节次 + 节数；单节次是节数为 1 的跨度）——对应导出文件里的 `rowspan`
- 地点：教室名 + **校区**（教室由"教室编号 + 校区"共同确定，同一编号在不同校区可能重复）

**同一门课一学期可以有多条上课安排**，一周上两次、中途换教师、换教室，各自独立。存储以**规则**为单位，不存每周快照（ADR-0001）。

**例外**（停课 / 线上教学）挂在既有的上课安排之上，记录"哪一教学周 + 哪种变化"。例外是信息，不是删除——ADR-0001 的理由是它让"改一次课"不至于变成"改一堆快照"。

### 周次集合

`周次集合`是周次唯一的内部表示。教务系统的四种写法——普通区间、单双周、断档周、特定周——**解析后全部落成同一个集合**，模型里不存在"这是单双周"这种类型。

- 表达形式建议用**整数集合**（去重、升序），不引入位图；位图是教务系统的内部实现，不是我们要暴露的形状。
- **必须可逆**：能从集合反向生成一个人能读的写法回填到编辑框，否则编辑一条导入的安排就会把它原有的写法抹掉。
- **单双周是可被表示的，但不需要专门存储**：`单周第5周-第15周`就是该区间内的奇数周集合。
- 编辑框接受的语法要**照教务系统那套**：`1-8 10 12-16`（空格分隔多段）、`单周第5周-第15周` / `双周第4周-第12周`。解析要宽容（容忍全角/半角、多余空格、缺"周"字）。

### 时间规则

- 一周从**周一**算起。
- **第 N 周 = 从开学那周的周一算起的连续 7 天**。
- 学期总周数**不写死**：周次导航的范围以数据实际范围为准，另留一个可配置的总周数。
- **学期设置**包含：第 1 周的第一天、学期总周数、作息时间表。
- 作息时间表有内置默认值（见 `docs/reference/ahpu-bell-schedule.md`）且**必须可改**；它是运行期数据，与具体学期无关时可复用。

### 导入

- 交互是**选文件**（手机浏览器下载的 `.xls`，或电脑导出后传手机）。明确不做粘贴文本导入。
- 解析输入是**原始文件的字节**：先按 GBK 解码，再当 HTML 解析。**不引入 Excel 解析库**。
- 每日节次数**按实际节次行数取步长，不写死 12**。
- 必须容忍教务系统模板自身的 bug（细则见 `docs/reference/ahpu-jwxt-export-format.md` 第五节）：
  1. 多条安排同格时，除最后一条外每条周次行**末尾缺一个 `)`**。
  2. **断档周用空格分隔区段**，不是逗号——先按第一个逗号切开，左侧整体是周次集合，再按空格切段。
  3. **停课额外单列一条**（`(2,停课(主校区))` 与 `(1 3-12,4J410(主校区))` 同格出现）。正常那条的周次集合**已经排除了那一周**，两条要合并理解为"一次带例外的排课"，**不能当成两次上课**。
  4. 单元格坐标按 `id` 定位（`n = 星期序号 × 每日节次数 + 节次序号`，星期序号 0 = 星期一），再用 DOM 顺序与 `rowspan` 交叉校验。
  5. 正文按**每两行一组**读：第 1 行 `课程名(课程号.班号) (教师)`，第 2 行 `(周次,教室(校区))`；空行全部丢弃。
- **解析必须有诊断输出，不允许静默丢弃。** 无法解析的格子要产出"哪一格、哪一行、原文是什么"的条目并能在预览页显示。静默失败是最糟的结果——这一条比"解析成功"更重要。
- **重新导入 = 整学期覆盖，不合并**（教务系统每次导出的都是全量）。

### 导入预览

- 预览页是**必需品而非锦上添花**：教务系统模板自身有 bug，解析器迟早会碰到没见过的写法。
- 预览页必须**明说会替换整学期**，并**警告手动标记的例外将被清除**（v0.1 不做例外保留）。
- 预览页的格子**可编辑**——让使用者当场修掉解析错的格子，不必先存一份错的再回来。
- 预览页给出汇总：解出多少条上课安排、有多少处需要留意。
- 确认后才写入数据库。

### 按周展开（core 的核心）

读取时把「上课安排 + 周次集合 + 例外」展开成「某个教学周里，每一天的每一节次上有什么」。消费它的是周网格、日后的"今日课程"和桌面小组件，**不是存储本身**。

展开要正确处理：

- 一条安排落在本周时占据它的**节次跨度**（连堂占多个格子）。
- 周次集合不含本周的安排**完全不出现**。
- **停课例外生效的那一周，这条安排不出现**（但它仍然存在，其他周照常）。
- 线上教学的例外改变的是地点那一项，不影响它出现与否。

### 冲突

先区分两件事：

- 同一格里**周次错开**的多门课是**常态**，不是冲突。
- **同一格 + 同一周 + 两条安排**才是冲突。

冲突时：**并排显示并标红**，详情里列出冲突双方，**不自动取舍**。理由：教务系统本不该产生这种数据，一旦出现就意味着"解析出错"或"教务系统改课表改出了重叠"——这是需要人眼介入的信号。静默吞掉其中一门，使用者可能一学期后才发现某门课从没被提醒过。

### 配色

课程颜色**按课程稳定分配、不入库、不上云**。稳定 = 同一门课在同一台设备上跨会话同色。分配依据建议用课程名称的稳定散列（导出文件里有课程号，但课程号在"手动添加"的场景下缺失）。

### 导出与导入（JSON）

- 自定义 **JSON**，**带版本号**（便于以后升级而不破坏旧文件）。
- 导出时**剥离学号 / 姓名 / 班级**。这是 ADR-0002 的前置条件，不是可选项。
- 导出范围：v0.1 导出**当前学年学期**（连同学期设置与例外），文件里带学年学期标识。
- 导入课表文件时：学年学期已存在则整学期覆盖（与普通导入语义一致）；不存在则新增并切过去。
- 不做 `.ics`（iCalendar 表达不了单双周、断档周、停课例外）。

### core 的接口形状

三个纯函数式入口，这是全部测试的落点：

- **解析**：`原始字节` → `课表` + `诊断列表`。诊断至少含严重程度（错误 / 提醒）、位置（星期 / 节次）、原文、说明。解析器的错误是**返回值的一部分**，不是异常。
- **展开**：`课表 + 教学周号` → `该周的格子`。格子里带它来源的那条安排与冲突标记。
- **序列化**：`课表` ⇄ `带版本号的 JSON`。反序列化遇到缺字段或版本不认识时返回明确错误，不抛异常。

数据层只是在 `core` 的数据形状与数据库之间做映射，不引入新的业务规则。

## 测试决策

### 什么算好测试

- **只测对外行为，不测实现细节。** 解析只断言"给定这些字节，解出哪些安排、报了哪些诊断"；展开只断言"给定课表和第 N 周，得到哪些格子"。断行为不断函数。
- **`core/` 不依赖 Flutter**，所以用最快的纯 Dart 单元测试反复砸，不需要 widget 测试基建。

### 测哪些

**解析**

- 端到端全量：拿真实导出文件的脱敏夹具跑完，断言**解出的安排条数与逐格内容**（验证标准是 `docs/reference/ahpu-jwxt-export-format.md` 记录的 **7×12 = 84 格全部解得出来、0 个无法配对**）。这是本规格最重要的一条测试。
  - **条数以夹具为准**：`test/fixtures/README.md` 的「结构指纹」数出来是 **14 条安排**。这份规格早先写过一个「15 条」，那个数字与夹具本身对不上——数法是 8 格有内容、16 条正文条目、其中 2 条是停课标记、合并后 14 条。规格、格式文档、两个 README 都已按夹具更正；再有出入时，**信夹具**。
- 模板自身 bug：末尾缺 `)` 的多条同格、空格分隔的断档周、停课单列一条与正常条合并。
- 未经样本验证的四种格式必须写用例但**不得声称"已验证"**（见 `docs/reference/ahpu-jwxt-export-format.md` 第六节）：单双周、断档周的标准写法、特定周、线上教学。
- 容错：非 HTML 文件、空的课表、缺表头的文件 → 必须返回明确错误，**不许静默产出空课表**。
- 诊断：构造一个解析不了的格子，断言它在诊断里**被指出来**，而不是被丢掉。
- 边界：周次 / 节次超范围、`rowspan` 超出 12 节、星期列数不是 7。

**展开**

- 周次集合 → 格子的映射：普通区间、单双周、断档周、特定周各自在本周出现 / 不出现。
- 连堂：跨 3 节的安排占 3 个格子、位置正确。
- 周次集合不含本周 → 一条都不出现。
- 停课例外生效的那一周不出现，其余周照常出现。
- 冲突：同一格同一周两条安排 → 被标记为冲突，且**两条都在**（没有被自动取舍）。
- 网格边界：一周 7 天 × 12 节，安排不会溢出到相邻天/相邻周。

**序列化**

- 往返：`课表 → JSON → 课表` 等价。
- **导出产物里不含学号 / 姓名 / 班级**——直接断言这件事，它是分享功能的前置条件。
- 版本号：老版本文件能被读；版本号缺失 / 不认识 → 明确报错。

**作息时间表**

- 默认值可用；节次 → 时刻的映射正确；改动后消费方拿到的时刻跟着变。

### 夹具与隐私

- 导入解析的**单元测试必须拿真实导出文件（的脱敏副本）当夹具**。编造的样本锁不住教务系统模板的那些坑。
- 原始文件含使用者的学号、姓名、班级，而**本仓库是 public**。入库前必须脱敏（替换成假值），且**脱敏结果给使用者过目**。这是硬约束。
- 脱敏只替换个人字段，**不改动任何结构**——改了结构就锁不住坑了。
- 脱敏后的夹具提交进仓库（建议 `test/fixtures/`），在任何机器上 clone 都能复现那次全量解析。
- 原始样本留在使用者下载目录，**不提交**。

### 不测什么

`data/`（drift）与 `ui/` 不写单元测试。v0.1 的复杂度全在 `core/`；数据层是薄薄一层存与取，UI 靠完成标准 2、3 手测覆盖。这是刻意的取舍，不是遗漏。

## 不在范围内

- **iOS**（无 Mac；`ios/` 目录冻结，不做任何假设性工作，见 ADR-0003）
- **服务器 / 账号 / 云同步**（ADR-0002）
- **自动登录抓取教务系统**——理由不是"难"，是**要在 App 里存使用者的教务系统密码，而 App 是要发给同学的**
- **粘贴文本导入**（复制会破坏 HTML 里的 `<br>` 分组）
- **`.ics` 导出**（表达不了单双周 / 断档周 / 停课）

## 待确认的假设

访谈中默认成立、但使用者没有逐条表态。**任何一条不成立都会改变实现**，在动工前确认一次：

1. 一周从**周一**算起。
2. 第 N 周 = 从开学那周的周一算起的连续 7 天。
3. 学期总周数**不写死**，以数据实际范围为准 + 一个可配置的总周数。
4. 导入 = 整学期覆盖，不合并。
5. 只处理**学生课表**，不含教师课表 / 班级课表。
6. 课程颜色在本地**按课程稳定分配**，不入库、不上云。

## 仍未确定的事实（不阻塞动工）

- **"第 1 周的第一天"的具体日期**目前空缺。教务系统导出的文件里**没有学期起止日期**，按已定方案它是**运行期数据**——使用者自己在 App 里填。内置默认值因此留空。
- **学期总周数**同样未知（样例课表最远排到第 18 周）。
- 两者使用者去教务系统的"选择教学周"下拉框看一眼即可确定，尚未查。
- `docs/reference/ahpu-bell-schedule.md` 里第四节→第五节的两格时刻是由规律推算的，使用者未逐格确认；若要精确到分钟值得再核一次。

## 完成标准

1. 导入后每一格与教务系统逐格对得上。
2. 连续一周，查课不再打开教务系统。
3. 手动加一条、改一条、删一条都不崩。
